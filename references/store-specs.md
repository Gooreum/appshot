# 스토어 제출 규격

공식 문서 기준 (2026-09 확인). 규정은 바뀌므로 제출 전에 원문을 한 번 더 본다.

- Apple — [Screenshot specifications](https://developer.apple.com/help/app-store-connect/reference/screenshot-specifications)
- Apple — [App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/) (2.3.3 / 2.3.7 / 2.3.10)
- Google — [Play Console: Add preview assets](https://support.google.com/googleplay/android-developer/answer/9866151)

## App Store (App Store Connect)

슬롯은 디스플레이 크기별로 나뉜다. 큰 슬롯만 채우면 작은 슬롯은 애플이 축소해서 쓴다.

| 슬롯 | 허용 해상도 (세로) | 필수 여부 | appshot 기기 |
|---|---|---|---|
| iPhone 6.9" | `1260×2736` · `1290×2796` · `1320×2868` | **6.9" 또는 6.5" 중 하나 필수** | `iphone-17-pro-max` (1290×2796) |
| iPhone 6.5" | `1242×2688` · `1284×2778` | 6.9"를 안 올리면 필수 | `iphone-14-plus` (1284×2778) |
| iPhone 6.3" | `1179×2556` · `1206×2622` | 선택 (없으면 6.5"를 축소) | — |
| iPhone 5.5" | `1242×2208` | 선택 | `iphone-8-plus` (1242×2208) |
| iPad 13" | `2064×2752` · `2048×2732` | **iPad에서 도는 앱이면 필수** | `ipad-pro-13` (2064×2752) |
| iPad 11" | `1488×2266` · `1668×2420` · `1668×2388` · `1640×2360` | 선택 (없으면 13"을 축소) | `ipad-air-11` (1668×2388) |

- 슬롯별 기기: 6.9"는 17 Pro Max·16 Pro Max·16 Plus·15 Plus 등, 6.5"는 14 Plus·13 Pro Max·11 등(노치 세대),
  5.5"는 8 Plus 세대. SE 3세대는 4.7" 슬롯이다
- 가로로 제출하려면 폭·높이를 뒤집은 값을 쓴다 (appshot은 세로만 만든다)
- 장수: 슬롯당 **1~10장**
- 형식: `.png` / `.jpg` / `.jpeg`, **알파 채널·투명도 불가**

### 심사 가이드라인 중 스크린샷 관련

| 조항 | 내용 |
|---|---|
| 2.3.3 | 앱이 **쓰이는 화면**을 보여줘야 한다. 타이틀 아트·로그인·스플래시만 있으면 안 된다. 텍스트·이미지 오버레이는 허용 |
| 2.3.7 | 스크린샷에 **가격**이나 스크린샷과 무관한 문구를 넣지 않는다 |
| 2.3.10 | **다른 모바일 플랫폼**의 이름·아이콘·이미지를 넣지 않는다 (Android 상태바가 찍힌 캡처 등) |

기기 프레임 사용은 금지되지 않는다.

## Mac App Store

iPhone·iPad와 달리 **기기 슬롯이 없다.** 허용 해상도 중 하나를 고르면 된다 — 전부 16:10 가로다.

| 허용 해상도 | appshot 기기 |
|---|---|
| `2880×1800` | `mac-16-10` |
| `2560×1600` · `1440×900` · `1280×800` | — (가장 큰 것을 올리면 애플이 축소해서 쓴다) |

- 장수: **1~10장**
- 형식: `.png` / `.jpg` / `.jpeg`, **알파 채널·투명도 불가**
- 기기 프레임(MacBook 목업)은 **필수가 아니다.** 앱 창만 올리는 Mac 앱이 많다.
  그래서 appshot의 macOS 기본값은 `theme.deviceFrame: false`다 —
  스크린샷에 넣는 것은 바탕화면이 아니라 앱 **창**이고,
  창을 노트북 베젤 안에 넣으면 바탕화면이 없어 어색해진다
- `appshot capture`는 macOS를 지원하지 않는다. `screencapture -o -l <창 ID>`로 **창만** 찍는다.
  화면 전체를 찍으면 열려 있던 다른 창의 내용이 그대로 스토어에 올라간다
- 2.3.3(앱이 쓰이는 화면)·2.3.7(가격 문구 금지)은 iOS와 똑같이 적용된다

## Google Play (Play Console)

### 필수 요건 (안 지키면 업로드가 안 된다)

| 항목 | 요건 |
|---|---|
| 형식 | JPEG 또는 24-bit PNG (**알파 없음**) |
| 변 길이 | 320px ~ 3840px |
| 비율 | **긴 변이 짧은 변의 2배 이하** |
| 장수 | 기기 유형을 **합쳐서 최소 2장**, 기기 유형당 최대 8장 |

### 추천 영역 노출 조건 (사실상 필수)

Play 곳곳의 추천 목록은 스크린샷을 크게 보여주는데, 여기 뜨려면:

- 앱: **4장 이상**, 최소 1080px. 세로는 9:16(최소 1080×1920), 가로는 16:9(최소 1920×1080)
- 게임: 16:9 가로 3장 또는 9:16 세로 3장

appshot 폰 기기(`pixel-9-pro-xl` · `pixel-9` · `galaxy-s25-ultra`)는 모두 `1080×1920`으로 출력한다.
기기 선택은 목업 생김새만 바꾼다.

### 대형 화면 (태블릿·크롬북)

- 최소 4장, 1,080~7,680px, 세로는 **9:16**
- 앱 화면이 아닌 추가 텍스트는 빼라고 권장 — 홈 화면에서 잘릴 수 있다

appshot 태블릿(`galaxy-tab-s10`)은 `1440×2560`(9:16)으로 출력한다.

### 콘텐츠 가이드라인

- 실제 앱 화면을 보여준다. 기기를 조작하는 손가락 등 사람을 넣지 않는다
- 태그라인은 필요할 때만, **이미지의 20% 이하**
- 금지 표현: 순위·수상·후기·가격·프로모션("Best", "#1", "Top", "New", "Discount", "Sale", "Million Downloads")
- 설치 유도 금지: "Download now", "Install now", "Play now", "Try now"
- 작은 글씨로 가득 채우거나 글자와 경쟁하는 배경을 쓰지 않는다
- 금방 낡는 문구(시즌 한정 등)는 피하고, 쓰면 제때 교체한다
- 태그라인·오버레이 텍스트는 로케일별로 번역한다
- **상태바 정리**: 알림·통신사 표시를 지우고 배터리·와이파이·셀룰러 아이콘은 가득 찬 상태로
- 흐리거나 늘어나거나 뭉개진 이미지, 뒤집히거나 기울어진 업로드 금지
- 피할 것: 허가 없는 타사 상표·캐릭터, **기기 이미지**("금방 구식이 되고 일부 사용자를 소외시킨다"),
  Google Play 등 스토어 배지·아이콘
- 스크린샷마다 대체 텍스트(alt text, 140자 이내)를 단다

Wear OS는 더 엄격해서 기기 프레임·추가 텍스트·배경이 **금지**다 (appshot 대상 아님).

## appshot이 처리하는 범위

| 규정 | appshot |
|---|---|
| 해상도·비율 | **자동** — 기기를 고르면 슬롯 규격으로 고정, `deviceScaleFactor: 1` |
| Mac 가로 규격 | **자동** — `mac-16-10`은 유일한 가로 기기라 레이아웃 치수가 따로 잡힌다 |
| Mac 기기 프레임 | **자동** — macOS 기본값 `theme.deviceFrame: false` (앱 창만) |
| 알파 채널 없음 | **자동** — 배경을 불투명하게 채워 RGB PNG로 출력 |
| 깨진·잘린 소스 이미지 | **거부** — 렌더 전에 사유와 함께 중단 |
| Play 기기 이미지 권장 | **자동** — Android 기본값 `theme.deviceFrame: false` (화면만). 켜면 경고 |
| Play 추천 노출 4장 | **자동** — Android 기본 4장. 4장 미만이면 경고 |
| 최대 장수 (iOS 10 / Android 8) | **경고** |
| 태그라인 20% | **경고** (Android) — 렌더 중 카피 띠 높이를 잰다 |
| 금지 표현·가격 | **경고** — iOS는 순위·가격, Android는 신규·설치 유도·다운로드 수까지 |
| 대형 화면 추가 텍스트 | **경고** (Android 태블릿) |
| 상태바 정리 | **자동** — `capture`가 iOS는 9:41·신호·배터리 가득, Android는 demo mode로 찍고 복구 |
| 실제 앱 화면인지 | **사람이 확인** |
| 다른 플랫폼 UI | **사람이 확인** — Android 목업에 iOS 캡처를 넣는 조합을 막지 않는다 |
| 번역·시즌 문구 | **사람이 확인** — 로케일별로 config를 바꿔 렌더 |
| 대체 텍스트 | **사람이 확인** — Play Console에서 직접 입력 |

## 실제로 리젝·반려되는 이유

1. **해상도가 1px이라도 다름** — 대개 `deviceScaleFactor`가 2로 잡혀 2배 크기로 나온 경우.
   `sips -g pixelWidth -g pixelHeight <파일>`로 확인한다
2. **알파 채널 포함 (App Store)** — 다른 도구로 후처리했다면 확인한다
3. **실제 앱에 없는 화면** — 가상의 UI, 미출시 기능
4. **다른 플랫폼의 UI** — Play 스크린샷에 iOS 상태바, 또는 그 반대
5. **가격·프로모션·순위 문구** — "무료", "50% 할인", "1위"
6. **텍스트가 잘림** — 목록 썸네일에서 긴 헤드라인은 읽히지 않는다 (한글 18자 / 영문 32자 경고)

## 참고

- 로케일별로 다른 스크린샷을 올릴 수 있다. `locale`을 바꿔 렌더하면 `{output}/{locale}/{device}/`로 분리된다
- 파일명 순서(01, 02 …)대로 올리는 편이 안전하다
