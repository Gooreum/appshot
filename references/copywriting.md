# 스크린샷 카피 작성

스토어 스크린샷의 헤드라인은 앱 설명문이 아니다. **스크롤을 멈추게 하는 문장**이다.

## 원칙

### 1. 기능이 아니라 결과를 쓴다

사용자는 기능을 사고 싶은 게 아니라 결과를 사고 싶다.

| ✗ 기능 | ✓ 결과 |
|---|---|
| 클라우드 동기화 지원 | 어디서든 이어보기 |
| AI 기반 자동 분류 | 정리는 앱이 알아서 |
| 오프라인 모드 제공 | 지하철에서도 그대로 |
| 다양한 통계 차트 | 이번 달, 한눈에 |

### 2. 길이

- **한글 18자 / 영문 32자 이내.** 스토어 목록에서 스크린샷은 썸네일로 표시되고,
  그 크기에서 이보다 길면 읽히지 않는다
- 서브카피는 2줄 이내. 3줄을 넘으면 디바이스 영역을 침범한다
- 서브카피는 없어도 된다. 헤드라인만으로 충분하면 비워둔다

### 3. 첫 장이 전부다

스토어 방문자의 대다수는 첫 스크린샷만 보고 스크롤을 넘긴다.
**가장 강한 문장을 1번에 쓴다.** 기능 나열 순서대로 배치하지 말 것.

순서를 정하는 기준:
1. 이 앱을 쓰면 무엇이 좋아지는가 (핵심 가치)
2. 그게 어떻게 작동하는가 (대표 화면)
3. 왜 다른 앱보다 나은가 (차별점)
4. 신뢰 근거 — 단, 사용자 수·수상·순위는 Play에서 금지 표현이다. 기능 자체의 숫자("3초", "12일째")로 대신한다
5. 마지막 밀어주기 (시작하기 쉬움)

### 4. 문체

- 명사형 종결(`~하기`)이나 평서형(`~합니다`) 중 하나로 **통일**한다. 섞으면 산만하다
- 물음표는 1번 장에서만. 여러 장이 질문이면 답답해진다
- 느낌표는 쓰지 않는다. 강조는 문장 자체로 한다
- 영문은 Title Case보다 Sentence case가 읽기 편하다

### 5. 쓰지 말 것

스토어 원문 규정은 `store-specs.md`에 있다. appshot 품질 게이트가 아래 항목을 경고한다.

- **가격·할인 문구** — App Store 2.3.7, Google Play 모두 금지. "무료", "50% 할인", "₩3,900"
- **순위·수상·최상급** — "최고의", "1위", "Best", "#1", "Top 10", "수상작"
- **다운로드·사용자 수** (Play) — "100만 명이 선택", "Million downloads"
- **신규 표현** (Play) — "New", "신규". Play가 명시한 금지어다
- **설치 유도** (Play) — "지금 다운로드", "Download now", "Try now"
- **경쟁사·다른 플랫폼 언급** — 대부분의 스토어 정책 위반
- **번역투** — "당신의 일상을 혁신하세요" 류. 실제로 말하듯 쓴다

### 6. 분량 — 이미지의 20%

Google Play는 태그라인이 **이미지의 20%를 넘지 말라**고 한다. appshot은 카피가 차지하는
가로 띠의 높이를 재서 20%를 넘으면 경고한다 (Android). 헤드라인 2줄 + 서브카피 2줄이면
대개 10% 안팎이다. Android 태블릿은 아예 텍스트를 빼라고 권장한다.

## 레이아웃과의 조합

| 레이아웃 | 카피 길이 |
|---|---|
| `caption-top` | 헤드라인 + 서브 둘 다. 가장 여유롭다 |
| `caption-bottom` | 헤드라인 중심. 서브는 짧게 |
| `angled` | 헤드라인만 권장. 디바이스가 시선을 가져간다 |
| `fullbleed` | 짧게. 배경이 앱 화면이라 긴 글이 묻힌다 |
| `duo` | 두 화면을 잇는 문장 하나 ("A에서 B까지") |

## 한글 특유의 문제

- **어절 중간에서 줄바꿈되면 읽기 나쁘다.** appshot은 `word-break: keep-all`로
  이를 막지만, 어절 하나가 줄보다 길면 넘치지 않게 그 어절만 강제로 끊는다. 긴 복합명사는 띄어 쓴다
- 한글은 같은 자수에서 라틴 문자보다 정보량이 많다. 영문 카피를 그대로 번역하면
  대개 길어지므로, 번역이 아니라 다시 쓴다
- 조사로 끝나는 문장(`~을`, `~를`)은 미완결로 읽힌다. 명사나 동사로 끝낸다
